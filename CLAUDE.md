# CLAUDE.md

Working rules for Claude Code on **LoonieToonie**, a household expense app (scan receipts, track spending, see how much you can save).

- **`specification.md`** is the full product and technical spec: data flow, spreadsheet schema, API, pages, storage roadmap, phases. Read the relevant sections before starting a phase.
- **`README.md`** has setup and run instructions.

## Layout and commands

| Folder | What | Check before committing |
| --- | --- | --- |
| `frontend/` | Vite + React + TypeScript PWA (Capacitor later) | `npm run lint && npm run build` |
| `backend/` | FastAPI (Python 3.12), venv in `backend/.venv` | `.venv/bin/ruff check . && .venv/bin/ruff format --check . && .venv/bin/mypy --strict app && .venv/bin/pytest` |
| root | `docker-compose.yml` (backend dev container) | `docker compose config -q` |

## Workflow

- Work on **one phase at a time** (phases are in `specification.md` §10). Wait for confirmation before starting the next, and mark the phase done in the spec when it is finished.
- When a design decision changes (schema, endpoints, flows, open questions), update `specification.md` in the same change.

## Architecture rules

- **No own database server for financial data.** All user data lives in the user's LoonieToonie spreadsheet and Drive folder. Do not add Postgres, SQLite, etc. without asking (see the storage roadmap in the spec).
- **All storage access goes through `backend/app/storage/`** (the `Repository` protocol, `SheetsRepository` for now). Routes and services never call `gspread` directly.
- **OAuth scope stays `drive.file`.** Never request broader Drive/Sheets scopes.
- **OCR runs on the device.** Only OCR text goes to Claude by default. Send the image only as a single retry when validation fails.
- **Claude output must be strict JSON**, enforced with tool use / structured output and validated on the backend (rules in spec §5).
- **IDs are UUIDs** generated by the backend.
- **Respect Sheets API quotas:** batch writes with `append_rows`, cache reads, never write row by row in a loop.
- Compute summaries in Python (pandas) after loading the tabs.
- React code calls one OCR function on every platform. Platform differences stay inside `frontend/src/ocr/`.

## Data rules

- Every synced tab has `updated_at` (ISO 8601 UTC) and `deleted` (`TRUE`/`FALSE`). Never hard-delete rows; set `deleted = TRUE`.
- If you change the schema, update `specification.md` §4 and add a migration that runs on login for existing spreadsheets.
- Never store bank tokens or other secrets in the user's Google Sheet.
- Never move to storage stage 4 (server-side PostgreSQL) without explicit approval. It changes the app's privacy promise.

## Secrets

- Real keys live in `backend/.env`, the repo-root `.env`, or `frontend/.env`, which are all git-ignored. Commit only `.env.example` files.
- Never put secrets in `VITE_*` variables; they are bundled into the browser code.
- Before committing, make sure no keys appear in the staged diff.

## Conventions

- Backend: type hints everywhere; Pydantic models for requests, responses, and the Claude JSON schema; pytest for tests. Test the receipt parser with sample OCR texts in several languages.
- Frontend: TypeScript strict mode, functional components and hooks.
- Money: decimal values with an explicit currency. Never use floats for totals in calculations. Default currency is `USD`.
- Dates: ISO 8601 (`YYYY-MM-DD` for purchase dates).
